# Git Rules

- Work on a feature branch or isolated worktree; do not implement directly on `main` unless explicitly approved.
- Keep commits reviewable and scoped to one coherent change.
- Inspect `git diff` before claiming completion.
- Do not rewrite shared history without explicit approval.
- Never commit secrets, generated private state, local candidate learning data, or unrelated files.
- Prefer descriptive conventional-style commit messages for public project history.
- Before PR/release, verify the branch is clean and required checks have actually run.
