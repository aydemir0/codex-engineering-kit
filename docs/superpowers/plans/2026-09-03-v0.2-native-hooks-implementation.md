# v0.2 Native Hooks Implementation Plan

**Goal:** Ship and prove Codex-native lifecycle hooks for the eight v0.2 events without relying on the disputed explicit plugin manifest `hooks` field.

**Spec:** `docs/superpowers/specs/2026-09-03-codex-native-plugin-v0.2-final-design-v2.md`

**First-party contracts used:**

- `openai/codex` hook config schema: `codex-rs/config/src/hook_config.rs`
- plugin hook environment: `codex-rs/hooks/src/engine/discovery.rs`
- command execution cwd/shell behavior: `codex-rs/hooks/src/engine/command_runner.rs`
- hook wire/output parsing: `codex-rs/hooks/src/schema.rs` and `codex-rs/hooks/src/engine/output_parser.rs`

## Fixed decisions

- Default plugin discovery path: `hooks/hooks.json`.
- Do not add a `hooks` field to `.codex-plugin/plugin.json`; RISK-001 remains open.
- Ship these active events: `SessionStart`, `SessionEnd`, `PreToolUse`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop`.
- Use one Python stdlib dispatcher: `hooks/scripts/hook_dispatch.py`.
- Plugin-installed command paths resolve through the first-party `PLUGIN_ROOT` environment injected by Codex.
- Unix command: `python3 "$PLUGIN_ROOT/hooks/scripts/hook_dispatch.py"`.
- Windows command uses the actual Codex default hook shell (`cmd.exe /C`): `py -3 "%PLUGIN_ROOT%\hooks\scripts\hook_dispatch.py"`.
- Hooks are synchronous unless a specific event later proves safe and useful as async.
- Hooks never install/enable/trust other hooks or skills.

## Phase B1 — Hook packaging contract

1. RED: add deterministic tests requiring valid `hooks/hooks.json`, all eight event declarations, command + `commandWindows`, bounded timeouts, no explicit manifest `hooks`, and a dispatcher file.
2. GREEN: add the smallest `hooks/hooks.json` and dispatcher skeleton that satisfy packaging without making unsupported behavioral claims.
3. Run Linux + Windows CI regressions.

## Phase B2 — Deterministic dispatcher behavior

Implement and unit-test event behavior in isolation:

- `SessionStart`: parse input, emit bounded `additionalContext`; no transcript injection.
- `SessionEnd`: deterministic cheap snapshot/evidence pointer only; no model call.
- `PreToolUse`: allow by default; deny only a narrow destructive-command fixture; no generic security claim.
- `PostToolUse`: emit bounded evidence metadata; never infer success only from invocation.
- `PreCompact`: persist minimal continuation marker.
- `PostCompact`: record compact transition.
- `SubagentStart` / `SubagentStop`: record bounded lifecycle metadata.

State/evidence writes must be under workspace `.codex-kit/`, use bounded JSON/JSONL records, and avoid raw transcripts/secrets.

## Phase B3 — Real Codex 0.147 acceptance

Use a disposable `CODEX_HOME` and the already-proven repo-local marketplace flow. The acceptance harness must:

1. install the plugin;
2. prove Codex discovers `hooks/hooks.json` through the default plugin path;
3. exercise hook trust rather than silently bypassing it;
4. trigger `SessionStart` and at least one normal `PreToolUse` + one destructive `PreToolUse` fixture;
5. prove normal use is allowed and destructive fixture is denied;
6. record sanitized hook evidence and raw-artifact SHA-256;
7. close only the events actually triggered.

If the public CLI has no deterministic hook-trust automation surface, use an operator-assisted acceptance step and document that boundary instead of fabricating a command.

## Phase B4 — Remaining lifecycle acceptance

Exercise and record:

- `PostToolUse`
- `SessionEnd` timeout behavior
- `PreCompact`
- `PostCompact`
- `SessionStart(source="compact")` round trip
- `SubagentStart`
- `SubagentStop`

Subagent events may remain blocked until the native-subagent vertical slice exists; do not fake them with standalone script invocation.

## Phase B5 — Desktop 0.152 compatibility

Repeat the supported hook acceptance subset against Desktop bundled Codex 0.152.0. Record behavior differences explicitly. Do not close RISK-001 unless the explicit manifest override is separately tested on both baselines.

## Acceptance gates

- `hooks/hooks.json` parses against repository contract.
- eight required events declared.
- plugin-root command resolution is portable across Unix/Windows command shells.
- dispatcher input/output fixtures pass.
- normal `PreToolUse` fixture is allowed.
- destructive `PreToolUse` fixture is denied with a deterministic reason.
- `SessionStart` context stays under project budget.
- `SessionEnd` handler stays within its configured budget.
- compaction round trip proven on real Codex.
- subagent lifecycle events proven only after real subagents exist.
- no public hook capability is promoted without matching real-runtime evidence.
