# v0.2 Worktrees, Domain Packs, and Context Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Plan E as an evidence-bound slice: real manual Git-worktree lifecycle acceptance, two narrow optional domain skills, and a pinned A/B/C context-efficiency benchmark protocol/reporting engine without promoting an unmeasured `lean` claim.

**Architecture:** Keep worktree support acceptance-only rather than building a custom worktree engine: a disposable Git fixture proves isolation, conflict-stop, and cleanup using native `git worktree` commands. Domain packs are ordinary progressive-disclosure skills with narrow trigger contracts. Benchmark code is Python 3 standard library, separates campaign definition from measured runs, pins five tasks to one repository fixture commit, requires exactly A/B/C × 5 tasks × 3 repeats for a complete campaign, and labels token evidence by source before aggregation.

**Tech Stack:** Python 3.11 standard library, Git/Git worktrees, Markdown, JSON, YAML metadata, GitHub Actions, existing Codex skill/plugin layout.

**Spec:** `docs/superpowers/specs/2026-09-03-codex-native-plugin-v0.2-final-design-v2.md`

## Global Constraints

- Worktree support follows the two-mode design; this plan implements deterministic manual Git-worktree acceptance and does not build a custom worktree engine.
- Manual creation uses `git worktree add --detach <path> <base-sha>` before a unique branch is created inside each isolated worktree.
- No two write tracks may share one worktree.
- Integration must stop on merge conflict; no semantic conflict resolution is guessed automatically.
- Cleanup may remove only fixture-owned worktrees and must verify no live fixture worktree remains before pruning stale metadata.
- `backend-patterns` and `frontend-patterns` remain narrow optional skills; no broad backend/frontend expertise claim is promoted merely because the files exist.
- Benchmark configurations are fixed as A = naive always-loaded instructions, B = progressive-disclosure skill routing, C = native isolated subagent delegation.
- Benchmark task set is fixed at five tasks before execution; each case records a pinned repository commit SHA.
- A complete initial benchmark requires 5 tasks × 3 configurations × 3 repeats = 45 real runs.
- A/B/C within one campaign must use the same model slug, reasoning setting, and Codex runtime version.
- Token source precedence is runtime/API measured usage, exported structured usage, then tokenizer estimate; estimated values remain explicitly labeled.
- Median plus range is reported for the initial three-repeat sample. Do not claim statistical significance.
- Do not promote the word `lean` as a measured capability until a real complete benchmark campaign exists.
- Core Plan E Python uses the standard library and repository-internal modules only.
- Runtime artifacts remain under gitignored `.codex-kit/`.
- RISK-001, RISK-002, the Codex CLI 0.147.0 SessionEnd discrepancy, and release compatibility remain outside Plan E.

The fixture procedure is exact:

1. create a temporary repository;
2. `git init`, configure fixture-only user name/email, create `shared.txt`, and commit the base;
3. create `track-a` and `track-b` with `git worktree add --detach ... <base-sha>`;
4. inside each worktree create a unique `cek-fixture-*` branch;
5. write and commit `track-a-only.txt` only in A and `track-b-only.txt` only in B; confirm cross-tree absence;
6. add conflicting edits to `shared.txt` in both worktrees and commit them;
7. require both source worktrees clean before integration;
8. merge A into the root fixture branch, then attempt to merge B;
9. require B merge to return non-zero with unmerged paths, immediately run `git merge --abort`, and record `conflict_stopped=True`; never edit the conflicted file;
10. remove only A/B fixture worktrees using `git worktree remove`, then verify `git worktree list --porcelain` contains no fixture path;
11. run `git worktree prune` only after the live fixture entries are gone;
12. emit no temporary paths in the persisted artifact.

Use `try/finally` so fixture cleanup is attempted after assertion-path failures.
