# v0.2 Native Plugin + Marketplace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the first Codex-native v0.2 vertical slice by shipping a valid plugin manifest and repo-local marketplace entry, testing their contracts in CI, and preparing a disposable real-CLI acceptance flow.

**Architecture:** Keep the first plugin manifest intentionally small and do not use the disputed explicit `hooks` manifest field. Repository-side tests validate stable schema/path/claim invariants without pretending to replace Codex ingestion. A separate local acceptance runner uses a disposable `CODEX_HOME` and the real `codex plugin` CLI to prove marketplace registration/install/list behavior.

**Tech Stack:** JSON, Python 3 standard library/unittest, GitHub Actions, PowerShell only for optional Windows operator convenience, Codex CLI `0.147.0` acceptance.

**Spec:** `docs/superpowers/specs/2026-09-03-codex-native-plugin-v0.2-final-design-v2.md`

## Global Constraints

- Manifest path: `.codex-plugin/plugin.json`.
- Repo-local marketplace path: `.agents/plugins/marketplace.json`.
- Plugin name: `codex-engineering-kit`.
- Development version: strict semver prerelease `0.2.0-alpha.1`.
- Do not put `hooks` in `plugin.json` in this slice; RISK-001 remains open.
- Do not bundle remote MCP in this slice.
- Skills path must be relative and use `./skills/`.
- Marketplace entry source is local and points to repository root relative to `.agents/plugins/marketplace.json`.
- No credentials, local usernames, cache roots, or installed-plugin inventory in shipped files.
- CLI acceptance must use a disposable `CODEX_HOME`; never mutate the user's normal `~/.codex` profile.
- Public acceptance evidence must be sanitized before commit.

Required tests:

```python
from __future__ import annotations

import json
import re
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
PLUGIN = ROOT / ".codex-plugin" / "plugin.json"
MARKETPLACE = ROOT / ".agents" / "plugins" / "marketplace.json"


class PluginContractTests(unittest.TestCase):
    def load_json(self, path: Path) -> dict:
        self.assertTrue(path.is_file(), f"missing {path.relative_to(ROOT)}")
        return json.loads(path.read_text(encoding="utf-8"))

    def test_manifest_identity_and_version(self) -> None:
        data = self.load_json(PLUGIN)
        self.assertEqual(data["name"], "codex-engineering-kit")
        self.assertRegex(data["version"], r"^0\.2\.0-alpha\.1$")
        self.assertTrue(data["description"].strip())
        self.assertEqual(data["license"], "MIT")
        self.assertEqual(data["skills"], "./skills/")

    def test_manifest_keeps_open_risk_out_of_primary_path(self) -> None:
        data = self.load_json(PLUGIN)
        self.assertNotIn("hooks", data)
        self.assertNotIn("mcpServers", data)
        self.assertNotIn("apps", data)

    def test_manifest_has_real_publisher_metadata(self) -> None:
        data = self.load_json(PLUGIN)
        self.assertEqual(data["author"]["name"], "aydemir0")
        self.assertEqual(data["repository"], "https://github.com/aydemir0/codex-engineering-kit")
        self.assertEqual(data["homepage"], "https://github.com/aydemir0/codex-engineering-kit")
        interface = data["interface"]
        self.assertEqual(interface["displayName"], "Codex Engineering Kit")
        self.assertEqual(interface["developerName"], "aydemir0")
        self.assertLessEqual(len(interface.get("defaultPrompt", [])), 3)
        self.assertTrue(all(len(prompt) <= 128 for prompt in interface.get("defaultPrompt", [])))

    def test_marketplace_points_to_local_plugin(self) -> None:
        data = self.load_json(MARKETPLACE)
        plugins = data["plugins"]
        self.assertEqual(len(plugins), 1)
        entry = plugins[0]
        self.assertEqual(entry["name"], "codex-engineering-kit")
        self.assertEqual(entry["source"]["source"], "local")
        self.assertEqual(entry["source"]["path"], "../..")
        self.assertEqual(entry["policy"]["installation"], "AVAILABLE")
        self.assertEqual(entry["policy"]["authentication"], "ON_USE")

    def test_no_placeholders_or_machine_paths(self) -> None:
        text = PLUGIN.read_text(encoding="utf-8") + MARKETPLACE.read_text(encoding="utf-8")
        self.assertNotRegex(text, r"\b(?:TODO|TBD)\b")
        self.assertNotIn("C:\\\\Users\\\\", text)
        self.assertNotIn("/Users/", text)
        self.assertNotIn("\\.cache\\", text)


if __name__ == "__main__":
    unittest.main()
```

### Task 3: Disposable real-Codex acceptance runner

- Test: `tests/test_plugin_smoke.py`

**Interfaces:**
- Produces command `python scripts/acceptance/plugin_smoke.py --codex codex --repo <repo> --output <json>`.
- The runner creates a temporary `CODEX_HOME`, registers the repository marketplace, lists marketplaces/plugins as JSON, verifies `codex-engineering-kit` becomes available/installed according to the real CLI response, and then deletes only the temporary home it created.
- It never reuses or mutates the operator's real Codex home.

- [ ] **Step 1: Write failing runner unit tests**

Create `tests/test_plugin_smoke.py` around pure helpers that must exist in the runner:

from scripts.acceptance.plugin_smoke import build_environment, find_plugin


def test_build_environment_replaces_codex_home(tmp_path):
    env = build_environment({"CODEX_HOME": "real"}, tmp_path)
    assert env["CODEX_HOME"] == str(tmp_path)


def test_find_plugin_checks_installed_and_available():
    payload = {
        "installed": [],
        "available": [{"name": "codex-engineering-kit"}],
    }
    location, plugin = find_plugin(payload, "codex-engineering-kit")

    assert plugin["name"] == "codex-engineering-kit"

- [ ] **Step 3: Implement minimal runner**

The runner must:

1. resolve `codex --version`;
2. create `tempfile.TemporaryDirectory(prefix="cek-codex-home-")`;
3. set only the child-process `CODEX_HOME` to that directory;
4. run `codex plugin marketplace add <repo-root> --json`;
5. run `codex plugin marketplace list --json`;
6. run `codex plugin list --available --json`; if this build rejects `--available`, fall back to `codex plugin list --json` and record the fallback;
7. locate `codex-engineering-kit` without assuming it is installed before the add/install stage;
8. attempt the version-appropriate add/install command only after discovery and record command/stdout/stderr/exit code;
9. emit sanitized structured JSON with runtime version, commands, exit codes, marketplace/plugin status, and no auth/cache content;
10. exit non-zero if plugin discovery/install cannot be proven.

Subprocess calls use argument arrays with `shell=False`.
