# Learning Workflow

## Entry conditions
A completed work session contains a potentially reusable engineering pattern and explicit evidence.

## Evidence required
Observed trigger, root cause/mechanism, successful intervention, reuse boundaries, and any repeated occurrences or user corrections.

## Procedure
1. Use `continuous-learning` to extract a candidate.
2. Remove secrets, personal data, private paths, and unnecessary project specifics.
3. Deduplicate against existing candidates/trusted guidance.
4. Assign category, scope, confidence, and `pending_review` status.
5. Present the candidate for human approval before promotion.

## Failure handling
Reject one-off noise, unsupported generalization, stale advice, secret-bearing content, and executable learned shell behavior.

## Verification
Validate candidate schema, redaction status, deduplication evidence, and confirm no trusted skill/rule was modified automatically.

## Output contract
Report accepted/rejected candidate counts, rejection reasons, redactions, duplicates, and exact candidates awaiting review.
